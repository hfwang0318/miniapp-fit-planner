# 严重性标准

Reviewer 和 Validator 共用此标准。任何 P0 或 P1 问题 → BLOCKED/FAIL。无例外。

| 级别 | 定义 | 示例 | 门禁影响 |
|------|------|------|---------|
| **Critical (P0)** | 核心功能崩溃、数据丢失、隐私泄露、安全漏洞 | 登录完全不可用、体重数据泄露给其他成员、云数据库权限开放 | **BLOCKED** — 必须修复才能继续 |
| **Major (P1)** | 路径缺失、静默失败、严重 UX 退化、错误处理缺失 | 网络异常时白屏、console 输出 `[object Object]`、云函数缺少 env 参数 | **BLOCKED** — 必须修复才能继续 |
| **Minor (P2)** | 外观问题、次要边缘情况、非关键路径优化 | UI 对齐偏差、长文本截断、非关键页面加载慢 | 记录但不阻塞合并 |
| **Observation** | 质量建议、未来考虑、可选重构 | "建议提取为公共函数"、"可考虑缓存" | 不阻塞，仅记录 |

## 使用规则

1. 任何 P0 或 P1 → 结论必须是 BLOCKED（Reviewer）或 FAIL（Validator）
2. 不得以"微小问题，超出本次范围"为由放过 P0/P1
3. 不确定严重级别时，取更高级别
4. 每个发现必须标注：级别、描述、文件:行号、证据
