# 质量门禁

合并前所有门禁必须通过。每道门禁单一 owner，责权明确。

## 门禁 1：需求澄清完成
**Owner**：主对话

- [ ] grill-me 已穷尽决策树，需求范围明确
- [ ] 需求 spec 已输出，包含明确的验收标准
- [ ] 如有陈旧文档，已标记为修复项

## 门禁 2：实现完成
**Owner**：Implementer

- [ ] 代码链追踪完整（有证据，有文件:行号）
- [ ] 所有发现已修复或记录
- [ ] `npm test` 全部通过（无新增 RED）
- [ ] 约束合规清单全部确认
- [ ] 实现报告已输出

## 门禁 3：审查通过
**Owner**：Reviewer

- [ ] 7 项审查清单全部评估
- [ ] 严重性按 rubric 正确分级
- [ ] 无 P0/P1 未解决问题（有 → BLOCKED）
- [ ] 审查报告已输出

## 门禁 4：验证通过
**Owner**：Validator

- [ ] 回归测试无新增 RED
- [ ] 至少一项非 mock 验证已完成
- [ ] `npm run test:e2e` 全部通过（或 `npm run test:e2e:doctor` exit 2 已记录）
- [ ] 陈旧文档修复项全部确认
- [ ] 验证报告已输出

## 最终决策

所有 4 道门禁通过 → 主对话收尾合并
任一门禁未通过 → 打回 Implementer（最多 3 次迭代，之后重新 grill-me）
